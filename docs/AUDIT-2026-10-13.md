# Georgia Opportunity Ledger audit — 2026-10-13

The system is **not ready for an unrestricted paid launch**. Public pages and
scheduled invocations work, but this audit found defects that the existing unit
suite and empty production data did not expose. This is an application and
configuration audit, not a penetration-test certification or a guarantee that
every possible path works.

## Billing repair follow-up

The billing findings below are historical findings addressed by the October 13
follow-up. Checkout now reuses open sessions, rejects duplicate subscriptions,
and serializes provider mutations. Downgrades and same-tier interval changes use
Stripe schedules. Upgrades use pending updates so declined payment retains the
paid tier. Closing an account queues durable cancellation, including direct
Supabase RPC calls; reopening and permanent deletion wait for cleanup.

Access now follows settled recurring invoice periods and prices. An asynchronous
payment cannot grant a higher tier merely because Stripe calls the subscription
active. The three-day failed-renewal grace period starts at the last paid period,
not the new unpaid month. Late events re-read Stripe, cannot replace a newer
subscription with an old cancellation, and use a conditional cache write.
Reconciliation processes the oldest 25 records in bounded batches every five
minutes, replacing the fixed first-500 scan.

The isolated Stripe sandbox `acct_1UPtSgFxjaLjx5xq` passed seven live API rehearsal
checks on API `2026-09-30.endive`: downgrade timing, paid upgrade, declined upgrade
and retained access, interval timing, checkout reuse/replacement, simulated
renewal, and cancellation of ordinary/scheduled subscriptions. Rehearsal clocks
and customers were deleted, checkout links expired, and test prices/products
archived. No live charge or customer mutation was used.

All 38 migrations apply from scratch. The existing RLS, deletion, purge, and
three concurrency checks pass, plus 15 billing coordination and six settled
access SQL checks. Deployment and production migration evidence is recorded
separately after release. Email delivery recovery, export coordination, scanner
setup, monitoring/backups, real inventory and human reviews remain open; the
billing repair does not establish overall launch readiness.

## Repairs in this changeset

- Fix opportunity detail requests that returned HTTP 500. Vercel logs confirmed
  an ambiguous PostgREST relationship between opportunities and industries.
  The query now names the primary-industry foreign key explicitly.
- Query locked previews by either UUID or literal slug. The previous raw OR
  filter treated slugs as UUIDs, ignored lookup errors and accepted filter
  punctuation. Database faults now remain faults rather than false 404s.
- Make the pricing and scoring comparison tables keyboard-scrollable on small
  screens, with accessible region names. Both failed the live Android axe audit.
- Delete expired export objects from Storage before clearing their database
  paths. Provider errors preserve the path for retry; individual failures are
  counted and other files continue. Cleanup is bounded to 100 files per run.
- Treat jobs with failed records as failed, return a non-2xx through the existing
  route, preserve progress and release the failed run's idempotency window.
  Running and successful invocations retain their duplicate protection. This
  allows a later invocation to retry; it does not add a scheduler retry policy
  or reclaim a worker killed before it records an outcome.
- Reconcile Stripe cancellation flags even when plan and period are unchanged;
  surface failed subscription writes, failed billing-event counts and failed
  export entitlement lookups rather than reporting false success.
- Upgrade Next.js to 15.5.27 and the affected dependency tree. Override nested
  PostCSS with its patched compatible version and update the test runner to
  Vitest 5.0.4. Node 22.12+ or supported newer versions are now required.
- Make deployed-environment browser checks fail on server errors instead of
  skipping them. Correct the report-list test: the deliberately public archive
  returns safe metadata, not report contents. Its response field allowlist is
  now asserted.

## Verification and limits

Baseline: 442 unit tests passed. The initial production browser run on desktop
Chrome and Android emulation had 126 passes, 4 failures and 4 skips. Two failures
were the outdated report-list expectation, two were mobile scrolling defects,
and the four skips concealed the opportunity-detail 500. Those are the reasons
for the test and code changes above; the baseline was not a clean result.

After the repairs, 457 unit tests across 44 files pass, including 15 added
regressions. `npm audit --omit=dev` reports zero vulnerabilities; the dependency
tree has no invalid peer relationships. Formatting, types, lint, schedule checks,
the production build and a clean-install dry run passed before deployment. The
build used the CI development configuration without production credentials.
Live browser checks must be repeated after the new deployment is Ready.

No customer account was created, modified, deleted or charged during this audit.
No extra reset email was sent. Stripe access was read-only and the connected
session exposed live accounts only, so successful checkout, renewal, downgrade,
cancellation, refund, payment-failure and webhook recovery journeys were not
tested against Stripe's sandbox. Authenticated tier tests, populated exports,
large batch jobs, Safari/WebKit behavior and a restored production backup also
remain unverified. The prior SQL/RLS/deletion regressions remain in CI; this
changeset adds no migration.
